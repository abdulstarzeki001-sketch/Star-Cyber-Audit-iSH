# إضافة Star Cyber Audit — لوحة محلية أولية

هذه إضافة مستقلة تساعدك على تجربة واجهة عربية وخريطة تفاعلية وربط GoClaw إلى جانب مشروعك الموجود. **هذه وحدة محلية منفصلة داخل المستودع ولا تعدّل محلل المشروع أو تنشر خدماته تلقائياً.** لا تتضمن GoClaw أو نموذجاً ذكياً؛ يجب أن تكون الخدمة الحقيقية مثبتة ومهيأة على جهازك قبل أن تعمل المحادثة.

## ما الذي يعمل؟

- واجهة عربية متجاوبة بدون اعتماد على خطوط أو مكتبات محملة من الإنترنت.
- قراءة إحصاءات تقرير `reports/analysis.json` المحلي (أو مسار محدد)، وفحص نقطة صحة اختيارية وGoClaw. لا يُرسل التقرير تلقائياً إلى GoClaw.
- مشهد تفاعلي بمنظور ثلاثي الأبعاد؛ الخطوط فيه توضيحية وليست رصداً لحركة الشبكة.
- محادثة عبر واجهة GoClaw الرسمية `POST /v1/chat/completions`، بعد ضبط الرمز والوكيل؛ يحتفظ الخادم بالرمز ولا يرسله للمتصفح.
- الواجهة تعمل على جهازك عبر `127.0.0.1` فقط، دون فتح منفذ عام.

## التشغيل على Kali أو WSL

1. افتح الطرفية من نسخة مستودع **Star-Cyber-Audit-iSH** على جهازك.
2. ادخل إلى مجلد الإضافة وشغّلها:

   ```bash
   cd tools/companion
   test -e .env || cp sample.env .env
   python3 app.py
   ```

3. على **نفس الكمبيوتر** افتح: <http://127.0.0.1:8055>
4. اترك الطرفية مفتوحة. لإيقاف الإضافة اضغط `Ctrl+C`.

المتطلب: Python 3.10 أو أحدث. لا يلزم `pip install` لهذه الإضافة. إذا كان المنفذ 8055 مستخدماً، غيّر `STAR_COMPANION_PORT` في `.env`.

## إعداد الاتصال بمختبرك وGoClaw

افتح ملف `.env` بمحرر نصوص محلي واضبط القيم:

```text
STAR_LAB_HEALTH_URL=
STAR_AUDIT_REPORT=
GOCLAW_BASE_URL=http://127.0.0.1:18790
GOCLAW_AGENT_ID=default
GOCLAW_GATEWAY_TOKEN=ضع_رمز_البوابة_هنا
STAR_COMPANION_PORT=8055
```

- اترك `STAR_AUDIT_REPORT` فارغاً لقراءة `reports/analysis.json` داخل المستودع، أو حدّد مسار تقرير محلي آخر. لا تظهر أسماء الملفات أو المسارات في الملخص.
- عيّن عنوان صحة المختبر إلى العنوان الصحيح بعد فحص مشروعك، مثل `http://127.0.0.1:8000/health` **إذا ثبت أنه العنوان الصحيح لديك**. فحص `/health` يبيّن استجابة العنوان فقط ولا يثبت هوية الخدمة أو أن جميع وظائفها تعمل.
- ثبّت وأعدّ **GoClaw Standard** بحسب [الوثائق الرسمية](https://docs.goclaw.sh/) وجهّز وكيلاً ونموذجاً. استخدم عنوان البوابة ورمزها الحقيقيين؛ قد يختلف المعرّف `default` في إعدادك.
- شغّل الإضافة والخدمات داخل بيئة محلية تستطيع الوصول إلى بعضها عبر `127.0.0.1`. إذا كان بعضها في WSL وبعضها في Windows أو حاويات Docker، يلزم فحص الاتصال الفعلي أو ترتيب توجيه محلي مناسب. إذا اخترت نموذجاً سحابياً فقد تُرسل رسائلك إلى مزوده.
- أوقف الإضافة وأعد تشغيلها بعد تعديل `.env`، ثم اضغط «تحديث الحالة» في الواجهة.
- لا تضع ملف `.env` أو رمز الوصول في GitHub، ولا ترسله في المحادثة.

## تشغيل Windows مباشرة

افتح PowerShell داخل نسخة المستودع:

```powershell
cd tools/companion
if (!(Test-Path .env)) { Copy-Item sample.env .env }
py -3 app.py
```

إذا كان ملف `.env` موجوداً وفيه إعداداتك، لا تنسخه فوقه. تحتاج Python 3 مثبتاً. للوصول من الهاتف تحتاج لاحقاً قناة وصول خاصة ومصادقة مناسبة؛ رابط `127.0.0.1` على الهاتف يشير إلى الهاتف نفسه.

## علاقتها بالأدوات الثلاثة

1. **GoClaw:** الإضافة تحتوي عميلاً للـAPI، وليست نسخة من GoClaw. تحتاج إلى تثبيت وتشغيل البوابة بشكل منفصل وضبط صلاحيات الوكيل المناسب.
2. **UI UX Pro Max:** استُخدمت إرشادات التصميم ونتائج البحث الخاصة بلوحة العمليات وتخطيط RTL عند إعداد الواجهة. المهارة نفسها ليست مثبتة داخل مشروعك بهذه الحزمة. لتثبيتها في مشروعك راجع [المستودع الرسمي](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill).
3. **3Dviz Pro Max:** استُخدمت إرشاداتها لفصل حالة الخدمة المقاسة عن العلاقات التوضيحية في المشهد. المشهد مكتوب خصيصاً لهذه الإضافة؛ المهارة والأمثلة الأصلية ليست مثبتة في جهازك. راجع [دليل التثبيت](https://github.com/viettranx/3dviz-pro-max/blob/main/docs/installation.md) لنسخ مجلد المهارة بالكامل إلى بيئة المساعد المدعومة.

رخصة مستودع GoClaw المذكورة عند إعداد الإضافة هي CC BY-NC 4.0؛ راجع ترخيصه ومتطلبات الاستخدام التجاري قبل الاعتماد عليه في منتج تجاري.

## الاختبارات

من داخل مجلد الإضافة:

```bash
python3 -m unittest discover -s tests -v
```

الاختبارات تستخدم خدمة محلية وهمية للتحقق من طلب المحادثة والصلاحيات؛ نجاحها لا يعني أن بوابة GoClaw أو نسخة المختبر على جهازك متصلتان. الاتصال الفعلي ببوابتك ونموذجك يحتاج تشغيلهما والتحقق منهما على جهازك.
