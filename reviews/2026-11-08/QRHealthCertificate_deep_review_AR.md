# تدقيق QRHealthCertificate — الشهادة الصحية وربطها بمنصة عبور

**تاريخ المراجعة:** 8 نوفمبر 2026. **المصدر:** ملف JavaScript رفعه المستخدم، وليس استجابة مباشرة جرى جلبها الآن من خادم الإنتاج. **النطاق:** تحليل ساكن لشيفرة الواجهة، دون تنفيذ المصدر أو تسجيل دخول أو تقديم طلبات API إلى المنصة الحكومية.

## 1. سلسلة الأدلة

- **الملف:** `QRHealthCertificate-Byvh35hk.js`.
- **الحجم:** 10,900 بايت (عدد محارف UTF-8 أقل من عدد البايتات).
- **SHA-256:** `78b26ef2ba7f02c92745bc9bc5e61731d4972a390ba3c866d62ae8e000788936`.
- **المكوّن الداخلي:** `QRHealthCertificate` في حزمة Vue/Vite مصغّرة.
- **الطلب المرصود:** `POST BorderPort_HS/read_doc_health` مع `url`, `x_coordinate`, `y_coordinate` وترويسة Bearer من سياق جلسة المستخدم.
- **نتائج الأداة:** 16 مؤشّر مصدر ثابت و13 اختبارًا اصطناعيًا ناجحًا. ليست 16 ثغرة مؤكدة.

## 2. سير العمل المثبت

1. يفتح الكاميرا الخلفية ثم الأمامية، ويستعمل `BarcodeDetector` وبديله `jsQR` عبر Canvas، مع إعداد `willReadFrequently:true` عند إمكانه.
2. يحاول قراءة خط العرض والطول من حالة `coords` المشتركة، وإلا يستدعي `navigator.geolocation.getCurrentPosition` مع مهلة 3 ثوانٍ؛ وقد تبقى القيمتين فارغتين.
3. إذا لم يبدأ محتوى QR بالنص `http` ينشئ رابط `/robot?url=` باستخدام `encodeURIComponent`.
4. يتحقق من وجود توكن ثم يعدّل ترويسة `Authorization` الافتراضية في Axios المشترك، ويرسل POST إلى `BorderPort_HS/read_doc_health`.
5. يقرأ البيانات من `response.data.data` إن وجدت، وإلا `response.data`؛ ثم ينسخ `is_main` من الغلاف الخارجي إن وُجد. **لا يثبت هذا معنى `is_main` الرسمي**.
6. يفحص محليًا تاريخًا ومدة صلاحية **48 ساعة** فقط عند غياب عبارة نجاح نصية في `a.message`، باستخدام أحدث تاريخ صالح من `date_str`, `date`, `created_at`, `license_approval_date`.
7. في المسار الذي يتجاوزه أو يجتازه فحص الصلاحية، يعرض رسالة إرسال ناجح، ويحفظ استجابة البيانات داخل `qrStore` و`sessionStorage['hc_print']`، ويحاول فتح صفحة `HealthCertificatePrint` ثم مسار `/dashboard/health-certificates/print` ثم تنقّل `window.location.href`.
8. في خطأ API بحالة HTTP `402` يعرض حالة `expired`; بقية الأخطاء تُعرض كفشل إرسال. **هذا سلوك واجهة، ولا يثبت سياسة صلاحية الخادم**.

## 3. مقارنة القارئات

| الوحدة | مسار API | مصدر الإحداثيات | وجهة العرض/التخزين |
|---|---|---|---|
| `QRHealthCertificate` | `BorderPort_HS/read_doc_health` | GPS/Geolocation إن توافر | `hc_print` ثم `HealthCertificatePrint` |
| `QRLocal` | `local_form/read_doc_company` | GPS/Geolocation إن توافر | `qrStore` و`QRDocument` |
| `QRImported` | `local_form/read_doc_company` | مركز QR داخل إطار الكاميرا **بالبكسل** | `qrStore` و`QRDocument` |
| `QrLocalImporter` | `support_org/read_qr_exitgate` عبر `useExitGate` | GPS/Geolocation إن توافر | `AchievementDocument` |

المقارنة مبنية على ملفات واجهة سبق تحليلها. تشابه أسماء حقول الإحداثيات لا يثبت تطابق ما يتوقعه كل API على الخادم.

## 4. نتائج المراجعة الـ16

| المعرف | الأولوية الهندسية | الدليل والأثر المحتمل |
|---|---|---|
| HC-01 | مرتفعة للمراجعة | وجود `/تم\|نجح\|نجاح.../` في رسالة الرد يتسبب **بتخطي فحص 48 ساعة**. وجود `تم` حتى في عبارة مثل «لم يتم» يكفي للمطابقة. ينبغي الاعتماد على رموز حالة وتعريف بيانات موثّق، لا نصوص نجاح محتملة. |
| HC-02 | مرتفعة للمراجعة | اختيار **أحدث** تاريخ من عدة حقول غير متجانسة يشمل `license_approval_date`; قد لا يمثل تاريخ بداية صلاحية الشهادة. يلزم حقل انتهاء صلاحية صريح صادر من الخادم. |
| HC-03 | مرتفعة للمراجعة | عند عدم وجود تاريخ قابل للتحليل (`NaN`) لا تُطبق المقارنة الزمنية ويستمر مسار النجاح؛ يلزم التعامل مع التاريخ المجهول كحالة «يلزم تحقق» لا نجاح مؤكد. |
| HC-04 | مراجعة العقد | `2880*60*1e3` يساوي 172,800,000ms = **48 ساعة** على ساعة جهاز العميل؛ لا دليل أنه قانون رسمي أو مصدر حكم لدى الخادم. |
| HC-05 | خصوصية | تسجيل `serverData` الكامل في `console.debug`; قد يشمل بيانات من الشهادة. لا يرصد هذا الملف طباعة التوكن صراحة. |
| HC-06 | خصوصية | حفظ استجابة الشهادة كاملة داخل `sessionStorage['hc_print']`, متاحة للشيفرة على الأصل أثناء الجلسة. |
| HC-07 | خصوصية | إضافة رد الشهادة إلى `qrStore`, الذي يرتبط بالتخزين المحلي؛ يلزم سياسة احتفاظ وتقليل حقول. |
| HC-08 | مراجعة الجلسة | تحديث `Axios.defaults.headers.common.Authorization` المشترك؛ قد يخلط سياقات مستخدمين/شاشات في التطبيق. |
| HC-09 | اعتمادية | مسار تكرار QR خلال ثلاث ثوانٍ ينفذ `return` دون جدولة إطار جديد؛ قد تتوقف حلقة الفحص. |
| HC-10 | دورة حياة | `onUnmounted` يوقف مسارات الكاميرا، دون إبطال صريح لحلقة `requestAnimationFrame`; احتمال نشاط زائد على الأجهزة الضعيفة. |
| HC-11 | دورة حياة | دالة إعادة المحاولة قد تستدعي فتح الكاميرا الذي يجدول فحصًا، ثم تجدول هي فحصًا آخر؛ احتمال حلقتين بالتزامن. |
| HC-12 | منخفضة | يفحص الإحداثيات بأسلوب truthy، فيستبعد `0` الصحيح كخط عرض/طول. |
| HC-13 | مراجعة العقد | قد يُرسل POST مع `x_coordinate` و`y_coordinate` فارغتين عند فشل تحديد الموقع؛ متطلبات الخادم غير معروفة. |
| HC-14 | اعتمادية | فشل حفظ `hc_print` يظهر تحذيرًا فقط، وقد يستمر الانتقال إلى صفحة الطباعة دون بيانات. |
| HC-15 | مراجعة العقد | تفسير HTTP `402` كحالة انتهاء صلاحية مثبت في العميل، وليس بالضرورة معنى عامًا للرمز أو مصدر الحقيقة النهائي. |
| HC-16 | مراجعة التاريخ | تجربة `Date.parse()` أولًا ثم معالجة نمط `DD-MM-YYYY` قد تؤدي إلى فهم تواريخ ملتبسة بصيغ مختلفة أو فروق مناطق زمنية. |

**هذه أدلة أنماط مصدر، لا إثبات استغلال أو خرق صلاحيات أو إمكانية إصدار شهادة مزورة.** لم تُفحص سلطة المستخدم أو قواعد الخادم أو قواعد بيانات الحكومة.

## 5. تدقيق إضافي مهم

- النسخة الحالية لا تنفذ POST تشخيصيًا ثانيًا عند الخطأ، بعكس سلوك رصدناه في `QRImported`؛ لا يجوز تعميم خطر تكرار POST على هذا الملف دون دليل.
- في هذه الوحدة، حالة `expired` قد تنشأ محليًا من حساب الوقت أو من HTTP 402. يجب فصل مصدر الحالة عند العرض والتدقيق.
- وجود `a.is_main` في الاستجابة لا يحدد تفسيره؛ قد يكون علمًا داخليًا لإحدى الشاشات أو آلية عمل أخرى.
- **التسمية `HealthCertificatePrint` وحدها لا تثبت أصالة PDF أو وجود توقيع رقمي**. يلزم مراجعة مكوّن الطباعة وعقد التحقق الرسمي.
- بعض أخطاء التنقل تؤدي إلى محاولات بديلة ثلاث، لكن عدم نجاح تنقل لا يعني نجاح عملية أصلية.
- رغم `willReadFrequently`, العمل على Canvas 1280×720 مع `jsQR` يستهلك موارد الهاتف، ومعدّل فحص 60ms ليس ضمانًا لعدد الإطارات الفعلي.

## 6. توصيات الإصلاح في بيئة تجريبية مخولة

1. اعتبار صلاحية الشهادة **قرار خادم** موثّقًا، له حقل `status` و`expires_at` موقّعان أو موثوقان؛ إبقاء المتصفح للعرض لا للحكم النهائي.
2. إزالة التحليل الإيجابي بالكلمات وإيقاف رسائل النجاح عند `success:false` أو غياب البيانات المطلوبة.
3. عدم اشتقاق انتهاء الصلاحية من تاريخ ترخيص المصنع أو أحدث تاريخ عام، أو ساعة الجهاز وحدها.
4. تقليل ردود الشهادة المخزنة ومسحها بعد الطباعة/الخروج، وعدم تسجيل تفاصيل `serverData` في الإنتاج.
5. إنشاء حارس واضح للحلقة والكاميرا، وتجنب جدولة RAF مزدوجة أو التوقف بعد QR مكرر.
6. فصل عميل Axios حسب الدور، وتحديد مدى إحداثيات GPS ومصدرها، وعدم إرسال قيم فارغة إن منعها العقد.
7. اختبار اختلافات `2026-11-08`, `08/11/2026`, والتوقيت المحلي/UTC على بيانات اصطناعية.
8. مراجعة `HealthCertificatePrint` و`useHealthCertificate-DVL2cDcP.js` قبل الاستنتاج عن صحة الوثيقة أو مطابقتها لقواعد الطباعة.

## 7. تشغيل الفحص المحلي على iSH

```sh
python3 tools/ish/qr_health_certificate_review.py /path/to/QRHealthCertificate-Byvh35hk.js \
  --qr-local /path/to/QRLocal-5TAaXbzM.js \
  --qr-imported /path/to/QRImported-C65Oqm1K.js
python3 -m unittest discover -s tests -p 'test_qr_health_certificate_review.py' -v
```

الملفان الإضافيان اختياريان للمقارنة فقط؛ الأداة لا تجري اتصالات شبكة ولا تنفذ JS. الفاحص خاص بصياغة هذا البناء المصغّر؛ قد تتغير أنماط المطابقة في إصدارات لاحقة.

## 8. الملف التالي المقترح

**`HealthCertificatePrint`** إن كان متوفرًا ضمن أصول Vite المنشورة في الإصدار نفسه، لأنه يعرض `hc_print` ويقرر كيف تظهر بيانات الشهادة بعد القراءة. ولتفسير `is_main` والحقول والتفويض، ستكون وحدة `useHealthCertificate-DVL2cDcP.js` أولوية موازية. يلزم الاسم المهاش الكامل كما يظهر في قائمة ملفات Vite؛ لا ينبغي اختراع رابط لم نرصده.
