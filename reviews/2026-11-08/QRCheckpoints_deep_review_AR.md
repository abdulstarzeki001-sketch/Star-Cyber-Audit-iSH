## 1. الوظيفة الفعلية

`QRCheckpoints` مكوّن **عرض سجل القراءات والسيطرات فقط**. لا يقرأ الكاميرا، ولا ينشئ QR، ولا ينفذ GET أو POST إلى منصة عبور، ولا يوافق أو يرفض الوثائق. يقدّم بطاقات متجاوبة (عمود واحد أو اثنان أو ثلاثة بحسب حجم الشاشة)، وتعرض لكل قراءة:
- اسم السيطرة: `doc_reader_org_name` أو `doc_reader_org`، وإلا شرطة طويلة.
- وقت القراءة: `time_stamp` منسقًا بـ`Intl.DateTimeFormat("ar-EG")`.
- إحداثيات `x_coordinate` و`y_coordinate` عند وجود أي منهما، مع زر ضمني لفتح موقعهما في Google Maps.

لا يعرض اسم الموظف أو رقم هاتفه في هذه النسخة، حتى إذا وجدا ضمن السجل. ولا يستعلم عن بيانات السيطرة مباشرة من الخادم.

## 2. مصادر البيانات وأسبقيتها

```text
QRCheckpoints(props.items)
   ├─ إن كانت items ذات length غير صفري: انسخها إلى state
   └─ وإلا، عند تركيب Vue فقط:
      1. history.state.read_doc إذا كانت Array (حتى لو فارغة)
      2. sessionStorage["qr_read_doc"] إذا كانت القيمة موجودة ويُحلّل JSON إلى Array
      3. query.read_doc عند غياب مفتاح sessionStorage:
         decodeURIComponent ثم JSON.parse ثم Array.isArray
      -> اعرض بطاقات السجل أو رسالة «لا توجد قراءات لعرضها»
```

**دقة السلوك:** تحديث `props.items` اللاحق يستعمل watcher مع `Array.isArray`، فيستبدل القائمة بمصفوفة منسوخة، بما فيها المصفوفة الفارغة. أما تغير `history.state` أو معامل `route.query.read_doc` بينما المكوّن ما زال مركبًا **فلا يسبب إعادة قراءة مستقلة** في هذه الوحدة.

### حالتا fallback تحتاجان انتباهًا

- إذا كان `history.state.read_doc=[]`، يختار المكوّن المصفوفة الفارغة ويوقف المرور إلى بقية المصادر، حتى لو امتلك sessionStorage قراءات.
- إذا احتوى `sessionStorage["qr_read_doc"]` قيمة موجودة لكن JSON غير صالح أو ليست مصفوفة، تُبتلع المشكلة داخل `catch{}` ولا يجرب معامل URL، لأن `else if` تابع لشرط وجود قيمة الجلسة.

**أهم خطر سلامة عرض:** لا يربط المكوّن أي قائمة احتياطية بمعرّف الوثيقة (لا يظهر فحص `doc_id` أو `certificate_number`). إذا وصل إلى بيانات محفوظة من سياق سابق، فقد تُعرض قراءات غير متعلقة بالوثيقة الحالية. لا يعني ذلك تغييرًا في قاعدة بيانات حكومية.

## 3. الربط المثبت مع QRDocument

من ملف `QRDocument-BJwpoEJY.js` المؤرشف في نفس المشروع ثبت:

1. الدالة المحسوبة `_.value` تختار `a.value.response?.read_doc` ثم `a.value.raw?.read_doc` ثم `a.value.read_doc`.
2. عند فتح سجل السيطرات: `sessionStorage.setItem("qr_read_doc",JSON.stringify(_.value||[]))`، وبعدها يتحول `w.value` إلى true.
3. نافذة «سيطرات القراءة» تعرض `QRCheckpoints` بتمرير `items:_.value`.

**الاستنتاج:** مسار العرض المعتاد يمرّر البيانات مباشرة عبر `props.items`، ولا يعتمد مبدئيًا على sessionStorage إذا وصلت عناصر في المصفوفة. لذلك **لا نعتبر عرض سجل قديم نتيجة مؤكدة عند كل فتح**. مسارات history/session/query تبقى مسارات احتياطية، ويصبح تلوث السجلات احتمالًا إذا كانت البيانات المباشرة فارغة أو غابت أو تغيرت حالة التوجيه/التخزين.

## 5. تفصيل اختلاف شروط إحداثيات الخرائط

في هذا الإصدار:

```js
function g(record) {
  return !!(record.x_coordinate || record.y_coordinate);
}
function f(record) {
  if (!record.x_coordinate || !record.y_coordinate) return;
  // open Google Maps...
}
```

- إذا توفر X فقط أو Y فقط، قد يظهر عنصر الموقع لكنه لا يستجيب للنقر.
- الإحداثي الرقمي صفر قيمة صحيحة في الخرائط، لكن شروط truthy تعتبره غائبًا. أما النص `"0"` فهو truthy، ما يجعل التقييم مختلفًا بحسب نوع البيانات.
- لا يظهر فحص حدود latitude من -90 إلى 90 وlongitude من -180 إلى 180، ولا يوجد تعريف رسمي يثبت أن x/y في كل مسارات المنصة يمثلان GPS لا إحداثيات صورة.
- الضغط على Google Maps يرسل الإحداثيات إلى طرف ثالث. الرابط لا ينفذ طلبًا تلقائيًا عند العرض، بل عند تفاعل المستخدم.

ينبغي التحقق من نوع ومصدر الإحداثيات وفق عقد API قبل وصف النقطة بأنها موقع جغرافي صالح.

## 6. التوقيت والهوية البصرية

يعالج `p(time_stamp)` النصوص المبدوءة بتنسيق تاريخ على شكل «YYYY-MM-DD HH:mm» باستبدال المسافة الأولى بـ`T`، ثم ينشئ `Date`. إذا احتوى النص كلمات `GMT` أو `UTC` أو الحرف `Z`، يختار `timeZone:"UTC"`؛ خلاف ذلك يعرض التاريخ وفق منطقة المتصفح. عند فشل `Intl.DateTimeFormat` يعود للنص الأصلي.

يوجد هنا **اختلاف محتمل في المنطقة الزمنية** بين قراءات متشابهة بصيغ مختلفة، وليس إثباتًا بأن أوقات الخادم خاطئة. يجب أن يثبت عقد البيانات ما إذا كان `time_stamp` يحتوي offset أو يمثل الوقت المحلي، وتوحيد سياسة العرض وفقه.

## 7. توصيات عملية للمختبر الذي تملكه

1. مرّر `documentId` إلزاميًا مع `items`، وامنع عرض سجل احتياطي لا يطابقه.
2. أزل fallback إلى مخزن محلي غير مقيّد أو خزّن `qr_read_doc` كحزمة تضم `documentId` و`reads` و`savedAt` ومدة احتفاظ محدودة.
3. اختبر `Array.isArray` عند التهيئة، مثل الـwatcher، ثم تعامل صراحة مع `[]` بوصفها نتيجة فارغة أو انتقل إلى fallback حسب سياسة واضحة.
4. بعد فساد JSON للجلسة، أظهر خطأً قابلاً للفهم أو جرّب المصدر التالي بشكل مقصود، دون تجاهل الخطأ بصمت.
5. وحّد شرط عرض الرابط وفتح الخريطة ليحتاج **كلا** الإحداثيين بعد التحقق من كونهما أرقامًا محدودة ضمن الحدود الملائمة.
6. أنشئ رابط الخرائط بـ`URLSearchParams`، مع عدم نقل إحداثيات حقيقية إلى طرف ثالث دون وضوح للمستخدم.
7. طبع الأوقات بتنسيق موحد مع منطقة زمنية معروفة، وأزل حالة التحميل الشكلية غير المرتبطة بعملية غير متزامنة.
8. استخدم معرّفًا ثابتًا لقراءة السيطرة بدل مفتاح فهرس القائمة إذا توفر.
