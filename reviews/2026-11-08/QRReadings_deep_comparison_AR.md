## 2. الوظيفة الدقيقة

`QRReadings` هو مكوّن Vue يعرض قائمة قراءات الوثائق وحقول البحث والتاريخ، ويتيح المعاينة وتصدير Excel حسب صلاحيات المستخدم التي يحصل عليها من `index-gleMzSil.js`.

بعكس `QrControlScan`، يحتوي `QRReadings` على منطق طلبات API مباشرة بدل استيراد composable `be()` من `useLocalCompany`. **ليس قارئ كاميرا أو مولّد QR**.

### حقول البحث الستة

1. `doc_reader_name` — اسم الموظف.
2. `doc_reader_org_name` — اسم الجهة.
3. `doc_reader_phone` — رقم الهاتف.
4. `doc_type` — نوع المنتج.
5. `time_stamp` — الوقت/التاريخ؛ يؤدي اختياره إلى ظهور حقول «من/إلى».
6. `doc_id` — رقم الوثيقة.

يتضمن العرض بيانات رقم الوثيقة، وموظف السيطرة، وجهة القراءة ورقم هاتفها، ونوع المنتج، والملاحظات ووقت القراءة، وزر معاينة اختياري.

## 3. مقارنة واجهتي سجلات QR

| وجه المقارنة | `QRReadings` | `QrControlScan` بواسطة `useLocalCompany.be()` |
|---|---|---|
| طلب سجل القراءات | `POST local_form/pagination_qrcode_reader` | `POST local_form/paginate_qrcode_reader2` |
| تنزيل Excel | `POST local_form/download_qrcode_readers` | `POST local_form/download_qrcode_readers2` |
| طلب معاينة | `POST local_form/return_doc_qrcode` | **نفس المسار** |
| حقول الاختيار | 6، تشمل الهاتف والجهة واسم القارئ | 3 فقط (نوع المنتج/الوقت/الرقم) |
| بيانات الصفوف | استجابة `data` تحول إلى `I.value` | استجابة `data` تحول إلى `serverReadings` |
| بيانات QR المحلية | `q.value` / `localStorage` | `readings` في composable، وليست الجدول المعروض |
| امتياز المعاينة | `return_doc_qrcode` | نفس النص |
| امتياز التصدير | `download_qrcode_readers` | `download_qrcode_readers2` |
| ملاحظات الصف | قد تُعرض بعنوان «سبب الرفض» | نفس الملاحظة |
| عمود فارغ | `colspan="5"` | `colspan="5"` |

**الاستنتاج المقبول:** هذه واجهتان/وظيفتان تستخدمان مسارات وسجلات مختلفة في العميل، وقد تكونان لأدوار أو إصدارات مختلفة. **غير المعروف:** هل تعودان إلى جدول قاعدة بيانات واحد؟ هل يعطيهما الخادم صلاحيات مختلفة؟ لا تجيب الشيفرة الأمامية عن ذلك.

## 4. تسلسل البيانات في QRReadings

```text
QRReadings (Vue)
  ├─ اختيار حقول البحث + إدخال التاريخ
  ├─ fetchServerReadings()
  │  └─ POST local_form/pagination_qrcode_reader
  │     └─ data -> قائمة الصفوف + pagination -> جدول
  ├─ previewServerReading(row)
  │  └─ POST local_form/return_doc_qrcode
  │     ├─ qrStore.add(entry) -> localStorage["qr_readings"]
  │     ├─ sessionStorage["qr_preview_entry"]
  │     └─ QRDocument (route state: preview/autoPrint/autoDownload)
  ├─ downloadByFilters()
  │  └─ POST local_form/download_qrcode_readers -> Blob -> Excel
  └─ loadReadings()
     └─ localStorage["qr_readings"] (مخزن محلي منفصل عن جدول الخادم)
```

في بداية إعداد المكوّن، عند وجود `window`، يستدعي الكود `loadReadings()` و`fetchServerReadings({page:1,per_page:10})`؛ لذلك تظهر بيانات الجدول من API إن نجح الطلب، بينما إدخالات localStorage التجريبية ليست مصدر صفوف الجدول مباشرة.

## 5. نتائج الفحص الآلي — 12 مؤشرًا

العدد **12** يعني أن 12 نمطًا معروفًا في نسخة الملف تطابق قواعد فحص نصي. **لا يعني 12 ثغرة فعلية.**

| المعرّف | الأولوية المقترحة | الملاحظة وأثرها المحتمل |
|---|---|---|
| RD-01 | متوسطة / فصل بيئات | يُدخل 3 قيود تجريبية `QRCODE:...` في `localStorage["qr_readings"]` عند غياب المفتاح. لا تدخل مباشرة في جدول الخادم، لكنها قد تختلط بمخزن تستخدمه شاشات أخرى |
| RD-02 | متوسطة / خصوصية | `console.debug` يسجل **الاستجابة الكاملة** لمعاينة الوثيقة، وقد تتضمن بيانات حساسة |
| RD-03 | متوسطة / خصوصية | `console.debug` يسجل الصف الكامل للقراءة قبل المعاينة، بما فيه حقول قد تخص موظفًا أو وثيقة |
| RD-04 | متوسطة / تكامل بيانات | تحويل `doc_id` إلى `Number` قبل المعاينة قد يغيّر الصيغة، ويجعل بعض المدخلات غير الرقمية `NaN`، الذي قد يُرسل كـ`null` عند JSON serialization |
| RD-05 | متوسطة / اعتمادية | يستخدم `const S=l.data||[]; I.value=S.map(...)` دون التأكد من كون `data` مصفوفة |
| RD-06 | مراجعة عقد استجابة | يعرض رسالة خطأ عند `success:false`، لكنه يواصل معالجة `data` إن وجدت، ما قد يعرض نتيجة رغم حالة خطأ |
| RD-07 | منخفضة / دلالة البيانات | يسبق أي `doc_notes` غير فارغة بعبارة «سبب الرفض» دون إثبات أنها فعلًا ملاحظة رفض |
| RD-08 | منخفضة / واجهة | صف «لا توجد بيانات» يمتد على 5 أعمدة، لكن الجدول يضم 6 أو 7 أعمدة |
| RD-09 | خصوصية / حسب الصلاحيات | يعرض `doc_reader_phone` مباشرة؛ يلزم تحديد من يُسمح له بعرض الرقم |
| RD-10 | خصوصية / تخزين متصفح | يُخزّن رد المعاينة في `sessionStorage["qr_preview_entry"]`، ويضيف سجلًا إلى `qrStore` أيضًا؛ ينبغي تقليل البيانات ومدة الاحتفاظ |
| RD-11 | مراجعة تجربة استخدام | ظهور زر Excel مشروط باختيار حقل صالح للتصدير **و** صلاحية `download_qrcode_readers` |
| RD-12 | مراجعة تفويض | يخفي زر المعاينة عند عدم وجود `return_doc_qrcode` في صلاحيات العميل؛ **صلاحية الخادم نفسها غير قابلة للإثبات من هذا الشرط** |

### مسائل إضافية تُراجع بشريًا

- فشل طلب جلب السجلات يُظهر خطأً، لكن لا يُمسح `I.value` صراحة؛ يمكن أن تبقى نتائج قديمة معروضة حتى جلب جديد.
- تصدير Excel يستخدم اسم ملف محتملًا من `content-disposition`، دون الحاجة إلى تقرير وجود ثغرة بمجرد استخدام `download`.
- لا يظهر هذا المكوّن حالة تحميل منفصلة للجدول، رغم استدعاء بيانات عند تهيئة الشاشة.
- يصدر من الدالة `previewServerReading` تسجيل إضافي لجسم الطلب في Console، إلى جانب الصف والرد.
- حقول الإحداثيات موجودة ضمن البيانات المطبّعة في الجدول، لكن المكوّن لا يثبت حقيقة GPS أو مطابقة الموقع الأصلي.
- تعرض المكونات قيمة `doc_notes` عن طريق النص المعروض في Vue، وهذا ليس إثبات XSS بذاته.
- من المفيد فحص `AppPagination.vue_vue_type_script_setup_true_lang-DzdlD2T5.js` لمعرفة طبيعة أحداث الصفحات والحدود.

## 6. التوصيات المرتبة

1. **أزل السجلات التجريبية من التخزين الفعلي**، واتركها في ملفات fixtures منفصلة.
2. **أزل Console logging للمحتوى الكامل**، خصوصًا ردود المعاينة وأرقام الهواتف.
3. **ثبّت عقد أنواع المعرفات**؛ لا تحوّل `doc_id` إلى رقم قبل معرفة ما إذا كان معرفًا نصيًا أو رقميًا رسميًا.
4. **تحقق من `success` وشكل `data`** قبل `.map`، وأفرغ نتائج البحث أو أظهر حالة «تعذّر التحديث» عندما يفشل الجلب.
5. **قلّل التخزين المحلي لرد المعاينة**، مع TTL وتنظيف عند الخروج.
6. **وحّد نموذج الواجهة عبر الشاشتين** فقط إذا أثبت عقد Backend أن المسارين مختلفان في الاسم لا في الصلاحية والوظيفة؛ لا توحد API بالتخمين.
7. **صحّح colspan والتسمية الدلالية للملاحظات**، وافصل حالات loading/empty/error.
8. **راجع صلاحيات الخادم في بيئة مخولة**؛ لا تعتمد على إخفاء الأزرار كوسيلة أمنية.

## 7. تشغيل أداة الفحص على iSH أو Linux

```sh
python3 tools/ish/qr_readings_offline_review.py /path/to/QRReadings-B-a3jcrk.js \
  --control /path/to/QrControlScan-M6uGJnR1.js \
  --composable /path/to/useLocalCompany-DfV5kpAj.js

python3 -m unittest discover -s tests -p 'test_qr_readings_offline_review.py' -v
```

الملفان الاختياريان مطلوبان معًا فقط للمقارنة، وإلا يمكن فحص `QRReadings` منفردًا. الأداة لا تتصل بالموقع، ولا تنفذ الشيفرة التي تفحصها، وتطبع مؤشرات وSHA-256 و3 مسارات API فقط. قواعدها مصممة لهذا الإصدار المصغر، وقد تحتاج تحديثًا إذا تغيّر بناء Vite.

## 8. النتيجة وحدود الإثبات

**مؤكد من المصادر:** وجود واجهتين لسجلات القراءات، مسارات مختلفة للسجلات والتصدير، مسار معاينة مشترك، بيانات تجريبية في سجل المتصفح، وكتابة معلومات الاستجابة في سجلات Console.

**غير مثبت:** جواز الوصول إلى سجلات دون صلاحية، تعديل قراءات في الخادم، أصالة رمز QR، سرّ توقيعه، أو أي خلل في قواعد قاعدة البيانات الحكومية.

**الملف التالي المقترح:** `QRDocument-BJwpoEJY.js` للتحقق من كيفية اختيار الوثيقة في المعاينة ومصدر بيانات `sessionStorage` مقابل `localStorage`، أو `AppPagination.vue_vue_type_script_setup_true_lang-DzdlD2T5.js` للتحقق من أحداث الصفحات.
