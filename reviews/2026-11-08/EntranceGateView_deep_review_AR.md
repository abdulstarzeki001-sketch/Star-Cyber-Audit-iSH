## 1. بنية الملف والاعتماديات

يصّدر `EntranceGateView` (بوابة الدخول)، ويتضمن مكوّنًا داخليًا `EntranceGateModel` لتجهيز قرار المعبر، مع modal لعرض تفاصيل المحطات مستورد من `StationsDetailsModal...js`، ومرفقات عبر `useAttachments-YD2hRx7D.js`.

يستخدم حالة مستخدم/صلاحيات من `index-gleMzSil.js`، وموقع الجهاز عبر composable مشتركة، والكاميرا عبر `getUserMedia`، ومكتبة `jsQR` المحلية. **لا يتضمن طبقة ORM أو قاعدة بيانات خادم.**

## 2. تسلسل القراءة والاستعلام عن الحمولة

```text
Open camera
  -> draw video frame on canvas
  -> jsQR(imageData)  [camera only; no BarcodeDetector in this file]
  -> accept scanned text only if it begins with https://
  -> ask shared GPS for latitude/longitude
  -> POST carrier_register/scrape_search_goods_gateway_register
     {url, x_coordinate, y_coordinate}
  -> if HTTP 200 and response.data.Agent_name is truthy:
       goodsData = response.data
       form.hash_id = response.data.hash_id
       show data / possible decision
```

في كود المسح الشرط حرفيًا: `!x.startsWith("http") || !x.startsWith("https://")`. في المنطق البولياني، يرفض `http://` ويقبل `https://` فقط، ويختلف عن `ExitGateView` الذي يسمح بكليهما. **المدخل اليدوي** يستدعي دالة البحث بالقيمة المدخلة من دون شرط HTTPS نفسه. لا يوجد تحقق مصدر صارم باستخدام URL parser أو allowlist في هذه الوحدة.

عند فشل البحث أو الرد الناقص، تظهر رسالة، لكن لا توجد عملية إفراغ صريحة لـ`goodsData` في بداية الدالة `searchImportedGoods`؛ إذا كان هناك سجل سابق ناجح، فقد يظل ظاهرًا بعد بحث لاحق فاشل حتى يستخدم المستخدم «مسح/إعادة ضبط». هذا خطر التباس في الواجهة، وليس دليلًا أن الخادم يقبل الطلب الثاني.

حقل `Agent_name` يُستخدم كمؤشر اكتمال رد الحمولة، وليس Schema تحقق متعدد الحقول. قد تكون بيانات جزئية موجودة مع غياب الحقل فتُرفض واجهيًا.

## 3. القرار والمرفقات: endpoint متغير حالة

يعرض زر «تسجيل القرار» عندما توجد الصلاحية النصية `gateway_decision` وتكون `goodsData.status === "غير محددة"`. هذا **إظهار زر** فقط؛ صلاحية الإجراء الفعلية يجب أن تُفرض في Backend.

يرسل عند تأكيد القرار:

```http
POST /api/carrier_register/gateway_decision
Content-Type: multipart/form-data
```

مع حقول `FormData`:
- `hash_id`
- `decision` (قيم الواجهة `APPROVED` أو `REJECTED`)
- `decision_reason`
- `x_coordinate` و`y_coordinate`
- `attachment[0]` و`attachment[1]` … لكل مرفق اختاره المستخدم

قبل الإرسال، تتأكد الواجهة من وجود بضائع محددة، وإحداثيات، ونوع قرار، وسبب غير فارغ. وتطلب إذن الموقع عبر المكوّن المشترك، لكنها تستعمل `latitude && longitude`، لذا تستبعد الصفر الرقمي عندما تظهر القيم أرقامًا في composable.

**ملاحظة اتساق:** بعد `await POST` تعرض دالة `submitDecision` نص «تم إرسال قرار الموافقة بنجاح» بشكل عام دون فحص حقل استجابة `success` أو تمييز `APPROVED` عن `REJECTED`. حالة رفض قد تُبلّغ برسالة «موافقة» حتى لو تم حفظ نوع القرار المرسل. الرد الناجح في Axios لا يثبت بمفرده اعتمادًا خادميًا نهائيًا.

## 4. نموذج التقاط المرفقات

يفتح `EntranceGateModel` كاميرا منفصلة لإرفاق صورة، يلتقط Canvas إلى `image/jpeg`، ثم ينشئ ملفًا `capture_<timestamp>.jpg` عبر `File` ويضيفه إلى مصفوفة المرفقات. توجد أيضًا وظيفة عرض مرفقات سبق حفظها، تنفذ تنزيلها عبر `useAttachments`.

المكوّن لا يوضح حد حجم الملف أو نوعه المقبول على الخادم، ولا ينبغي تخمين سياسة الخادم من قابلية اختيار ملف داخل الصفحة.

## 5. نقطة الأمان الأعلى أولوية

هذه الشاشة تجمع بين **استعلام قراءة بيانات** و**عملية تسجيل قرار مؤثرة**. يجب الفصل بين حالاتهما: نجاح HTTP في استعلام البضاعة لا يعني الموافقة، وظهور زر `gateway_decision` لا يعني تفويض الخادم. يجب مراجعة التفويض والتثبت من `hash_id` ومن حالة الحمولة لحظة الطلب لدى النظام المملوك وضمن الاختبارات المصرح بها.

## 6. أهم تحسينات نسخة تدريبية مملوكة

| أولوية | المشكلة في الواجهة | التحسين |
|---|---|---|
| P1 | قرار `gateway_decision` يتكل على صلاحية/حالة عرض | تحقق إلزامي على الخادم من الهوية وحالة `hash_id` ومنع إعادة القرار |
| P1 | رسالة موافقة عامة بعد الطلب حتى لقرار رفض | افصل نجاح النقل عن النتيجة، واعرض نوع القرار الفعلي |
| P2 | فشل بحث جديد لا يُلغي سجل `goodsData` السابق صراحة | امسح حالة البضاعة والمعرّف قبل بداية بحث جديد، واربطها بمعرّف القراءة |
| P2 | الكاميرا تقبل HTTPS، والإدخال اليدوي غير متناظر معها | سياسة مدخل URL موحدة، وخادم يحدد الوجهات المسموحة |
| P2 | الصفر الرقمي مرفوض بانتقاء truthy | تحقق من `Number.isFinite` ومدى GPS وحدود التفويض بشكل مستقل |
| P2 | فحص `Agent_name` وحده | Schema مهيكل للرد ومطابقة الجهة/رقم المركبة حيث ينطبق |
| P3 | معالجة Canvas في كل إطار دون throttling ظاهر | تقليل استهلاك الموارد ومعالجة الكاميرا عند الخروج |
| P3 | سياسة المرفقات غير ظاهرة هنا | فحص MIME والحجم والعدد، وحفظ/تنزيل آمن في الخادم |

## 7. مقارنة مع ExitGateView

`ExitGateView` قارئ خروج أخف: لا يحتوي على form `gateway_decision` أو حقول مرفقات. يتبع `useExitGate.searchImportedGoods` الذي يستدعي `support_org/read_qr_exitgate` ضمن الملف المستورد. إذًا بوابة الدخول والخروج **ليستا endpoint واحدًا ولا إجراءً واحدًا**.
